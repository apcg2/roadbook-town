# 自驾规划规则


1. **硬约束优先。** 尊重起终点、日期、总天数、必去地点、末日抵达时限和同行限制。先核验能否完成，再丰富内容。
2. **顺路与体验平衡。** 优先安排路线走廊内的城市，减少无意义往返。为值得停留的景点绕行时说明新增里程和时间，由用户判断；不把最短距离视为唯一目标。
3. **按真实公路计算。** 不以城市直线距离推算车程，区分高速、山区和城区接驳时间。城市内景点间移动、停车场到住宿城市的往返计入驾驶总量。
4. **默认舒适节奏。** 建议普通游玩日驾驶不超过约4小时；纯转场日可放宽至约6小时。超过默认值时在草稿提出减点、加天或调整路线的选项。这是产品安排目标，不是安全保证或法规标准。
5. **按完整一天排程。** 驾驶、游玩、吃饭、停车、步行接驳和休息共同占用时间；建议预留约20%弹性，避免把每分钟排满。以早上、上午、下午、晚上为主要颗粒度，不制造精确到分钟的确定性。
6. **景点充足且不重复。** 每个途中城市直接安排2—3个不同景点，同时保持每天最多3个。时间或可靠资料不足时允许该城市仅1个，但须记录sightShortfallReason；不得安排0个、重复POI、别名重复或用不同入口冒充不同景点。高强度、需预约、开放时段有限的项目单独核验，不机械凑数量。
7. **驾驶时间不等于承诺。** 记录查询时间与算路策略，未来日期的拥堵、临时封路等不能由当前接口保证。节假日安排更宽松，过长返程优先拆分。
8. **住宿以次日出发便利为依据。** 推荐到地级市、县级市或县城，不主动推荐具体酒店。避免为了省一晚住宿而安排明显过长的夜间转场；多日游玩集中时优先连住。
9. **城市与景点分层。** 城市层是停留和住宿单位；景点层必须核验实际位置。具体 POI 优先选择驾车可达入口或停车位置，不能把山顶、湖中心当驾车终点。
10. **美食到菜品。** 每个途中停留城市固定5项有来源的地方食物，不指定餐厅、套餐或团购；结合忌口，减少邻近城市重复条目。少于或多于5项、空列表、同义重复及无有效来源均阻止出稿。出发/结束专用节点不展示美食；有实际游玩的同城中途段可展示。
11. **以证据判断推荐。** 小红书用于体验与口碑线索，高德用于位置和道路，官方景区信息用于核验开放、预约及限制。平台热度不能单独证明值得去。
12. **未知信息如实保留。** 无可靠地址不伪造坐标；泛地点经说明后采用城市中心。具体景点未定位时暂不生成声称真实完整的线路图。缺少口碑不得编造好评或差评。
13. **天气与季节分开。** 三日实时天气仅供近期查看；远期出游安排不拿当天预报代替，可把季节性信息作为有来源的规划参考。
14. **不代替用户扩大范围。** 不自动加入酒店推荐、购物、门票购买、住宿预订或额外活动。完成确认后的文本才进入网页。


## 来源处理



景点查询链路：城市＋景点/游玩/周边 → 核验主景点与驾车入口 → canonicalAttractionId、POI和名称三重去重 → 笔记正文详情 → 广告筛选 → 排入2—3个景点。禁止采集评论。

美食查询链路：地名＋美食/特色美食/特色小吃 → 提取菜品 → 结果少或关联不清时用地名＋菜品逐项补查 → 去重与广告筛选 → Redfox仍不足时使用当地政府或文旅官方资料 → 保留5项。搜索结果不直接证明目的地关联或推荐价值。

优先相关、近期、不同作者的真实体验；季节性地点同时关注相同季节。建议每个正式推荐景点争取至少3位不同作者的有效样本，默认近12个月优先，但样本数量与时间不能代替内容质量判断。

剔除明显合作、置换、团购、联系方式引流、重复营销模板及与实际地点无关的内容。广告识别存在不确定性，只能降低干扰，不能宣称已百分之百排除。

保留私有来源记录：正文链接或标识、获取时间、支持的结论、广告排除原因、置信状态。页面不展示用户名、头像或复制长文，不把推测包装成“小红书网友”的结论。
